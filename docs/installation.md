# Install and maintain KKdesign-kit

B1 preview 0.2.0a1. Requires Python 3.9+ on macOS, Linux or Windows and a separately
installed/authenticated Codex CLI or Claude Code. Packaging and installation use
only the Python standard library. Offline contract validation also needs
`python -m pip install -r requirements.txt`; use a virtual environment outside the
installed skill. Nothing installs Hoangsa, Impeccable, hooks or MCP configuration.
See [compatibility](compatibility.md) for measured harness support.

## From source or portable artifact

From the checkout root, build a ZIP outside the source directory:

```sh
python scripts/kkdesign_install.py package --output ../kkdesign-kit-0.2.0a1.zip
```

Unzip to a folder of your choice. Run commands below inside its `kkdesign-kit/`
directory (or from the checkout root). With an absolute script path, quote it;
the payload is located relative to that script, not your current directory.
No runtime download or access to the original checkout is needed.

Choose one harness and one scope explicitly. Example, project install:

```sh
python scripts/kkdesign_install.py install --harness codex --scope project --project "/path/to/project with spaces"
python scripts/kkdesign_install.py inspect --harness codex --scope project --project "/path/to/project with spaces"
```

For Claude Code replace `codex` with `claude-code`. For personal installation use
`--scope user`; `--project` then only supplies context for conflict detection.
`--home` overrides the personal root for isolated tests; it does not configure the
harness. Normally omit it. Windows accepts quoted native paths such as
`"C:\Work\Project with spaces"`; use `py -3` if `python` is not available.

| Harness | User scope | Project scope | Invoke after restarting harness |
|---|---|---|---|
| Codex | `~/.agents/skills/kkdesign-kit` | `<project>/.agents/skills/kkdesign-kit` | `$kkdesign-kit` |
| Claude Code | `~/.claude/skills/kkdesign-kit` | `<project>/.claude/skills/kkdesign-kit` | `/kkdesign-kit` |

Codex gets its display metadata from `agents/openai.yaml`. Claude Code uses the
canonical frontmatter name and description, plus native slash invocation and
skill-directory/argument substitution. There is no second authored SKILL.md,
plugin, settings merge, or hook adapter to enable.

Bare invocation displays the bundled menu. `package` works in B1; `init` and
`refresh` await B2; `design`, `review` and `prototype` await B3; `learn` is planned.
Unavailable commands must report their status without performing the operation.

## Inspect, update, rollback, uninstall

Use the same `--harness`, `--scope`, `--project` (and `--home` if overridden) for
all lifecycle operations. For example:

```sh
python scripts/kkdesign_install.py update --harness codex --scope project --project "/path/to/project with spaces" --source "/path/to/new extracted/kkdesign-kit"
python scripts/kkdesign_install.py rollback --harness codex --scope project --project "/path/to/project with spaces"
python scripts/kkdesign_install.py uninstall --harness codex --scope project --project "/path/to/project with spaces"
```

Repeat installation of identical bytes returns `unchanged`. A different payload
requires `update`; each update keeps one previous version. Rollback swaps the
current and previous versions, so it can be undone. SHA-256 covers the entire
installed tree, including unexpected files. These hashes detect modification;
they are not publisher signatures. Obtain artifacts from a trusted source.

Ownership records and the previous version live outside discovery directories:
`<scope root>/.kkdesign-kit/installations/<harness>/`. Uninstall removes the
managed skill, its previous version and ownership records. Empty directories can
remain. Project DESIGN.md, lessons, profiles, task history and unrelated settings
or credentials are never collected, overwritten or removed.

## Conflicts and troubleshooting

- `inspect` reports `absent`, `managed`, `modified` or unmanaged `conflict`, plus
  other same-name user/ancestor-project installs (and legacy Codex personal skill
  or Claude command files). Install/update/rollback refuse detected shadows.
  Admin-managed paths and harness-specific external search roots must also be
  checked with that harness's discovery UI; the installer cannot enumerate them.
- No force-overwrite flag: move an unmanaged installation to a safe location,
  or preserve local edits outside the skill before restoring a managed payload.
  Do not place project data, virtual environments or generated bytecode inside
  the installed skill. Modified backups also block lifecycle mutations.
- Symlinked installation ancestors or payload files are rejected. Select a real
  directory rather than a linked home/project path.
- A lock prevents concurrent mutations. An interrupted operation may leave a
  lock or staging folder. Inspect target, `state.json`, `previous/` and staging
  before recovery; preserve them first. Remove a stale lock only after verifying
  no installer process is running. Do not delete staging blindly: it may hold
  the recoverable previous installation.
- Skill not found: restart, verify the path above, inspect conflicts and check
  workspace trust/managed policy. Cloud harnesses and Desktop skill syncing are
  outside this CLI evidence. Installer success alone does not prove discovery.
- A missing external design tool is not an installation failure. B1 does not
  execute Figma or certify live UX, accessibility, performance or human approval.
